# 七星彩选号（四人委员会 · 按位对抗验证 Workflow）

## ⚠️ 执行方式（硬性·最高优先级）

**本 Skill 的唯一执行入口是 Workflow 工具。** 当 Skill 被调用时：

1. **立即**使用 `Workflow` 工具，参数 `scriptPath` 指向本 Skill 目录下的 `scripts/workflow.js`
2. **禁止**手动实现选号逻辑、禁止手动写 Python 脚本算频率/趋势/选号
3. **禁止**跳过 Workflow 直接输出预测结果

```
Workflow({scriptPath: ".claude/skills/qixingcai-picker/scripts/workflow.js"})
```

Workflow 自动完成：数据准备 → 四人按位独立提名 → 全互审对抗验证（最多 5 轮收敛）→ 首席裁定 → 返回最终前6+后1。

---

## Workflow 架构（参考）

### 四人委员会（无形态侦探——七星彩无连号/重号约束）

| 委员 | Agent Type | 方法论 |
|------|-----------|--------|
| 趋势猎手 | trend-hunter | 按位四窗口频率曲线判定数字趋势方向 |
| 遗漏判官 | gap-judge | 盯每位遗漏和历史极值，找超跌回补信号 |
| 结构大师 | struct-master | 按位奇偶/大小/跨度框架选号 |
| 博弈鬼才 | game-theorist | 反共识选号，回避过热数字和大众心理号 |

### 执行阶段

1. **数据准备** — 单 Agent 读取 `qxc_draws.csv`，提取全历史 + 近 50 期按位统计上下文
2. **独立提名** — 4 Agent 并行，各自按位独立分析，提名 d1–d6（前区 0–9）+ special（后区 0–14）
3. **对抗验证** — 最多 5 轮循环：互审→自证→收敛检查
4. **未收敛兜底**（若 5 轮未收敛）— 加权投票排名 + 最终陈述
5. **首席裁定** — Opus 模型综合辩论记录 + 共识 + 权重，输出最终一注

---

## 原则

- 彩票为随机游戏，历史统计**不能**保证未来结果。输出必须声明：娱乐目的、概率本质、过往统计仅供参考。
- **只出一注**：前区 6 位 + 后区 1 位，不撒网。
- **时间戳规则（强制）**：`最后更新`、`预测生成时间` 使用北京时间 ISO-8601（`+08:00`）。

## 玩法说明

- 前区 6 位（d1–d6），每位 0–9，允许重复
- 后区 1 位（special），0–14
- 按位匹配，无连号概念、无重叠约束

## 数据来源

`data/processed/qxc_draws.csv`（优先），否则回退 `data/raw/`。

## 落盘约定

Workflow 完成后，结果由调用方（Agent）负责写入：

| 文件 | 内容 |
|------|------|
| `history/qixingcai_analysis.md` | 按位走势面板 + 结构快照 |
| `history/qixingcai_prediction.md` | 最终一注 + 选号逻辑 + 委员会辩论摘要 |

## 职责隔离

**仅七星彩**。其他彩种用各自独立 Skill。禁止数据采集、全流程编排。
