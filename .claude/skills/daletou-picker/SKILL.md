# 大乐透选号（五人委员会 · 对抗验证 Workflow）

## ⚠️ 执行方式（硬性·最高优先级）

**本 Skill 的唯一执行入口是 Workflow 工具。** 当 Skill 被调用时：

1. **立即**使用 `Workflow` 工具，参数 `scriptPath` 指向本 Skill 目录下的 `scripts/workflow.js`
2. **禁止**手动实现选号逻辑、禁止手动写 Python 脚本算频率/趋势/选号
3. **禁止**跳过 Workflow 直接输出预测结果

```
Workflow({scriptPath: ".claude/skills/daletou-picker/scripts/workflow.js"})
```

Workflow 自动完成：数据准备 → 五人独立提名 → 全互审对抗验证（最多 5 轮收敛）→ 首席裁定 → 返回最终一注。

---

## Workflow 架构（参考）

### 五人委员会

| 委员 | Agent Type | 方法论 |
|------|-----------|--------|
| 趋势猎手 | trend-hunter | 四窗口频率曲线判定号码趋势方向 |
| 遗漏判官 | gap-judge | 盯遗漏和历史极值，找超跌回补信号 |
| 结构大师 | struct-master | 先定奇偶/大小/和值框架再选号 |
| 形态侦探 | pattern-spy | 盯连号/重号/区间形态 |
| 博弈鬼才 | game-theorist | 反共识选号，回避过热号和大众心理号 |

### 执行阶段

1. **数据准备** — 单 Agent 读取 `dlt_draws.csv`，提取全历史 + 近 50 期统计上下文
2. **独立提名** — 5 Agent 并行，各自按方法论分析数据，提名前区 5 码 + 后区 2 码
3. **对抗验证** — 最多 5 轮循环：
   - 每人对其他 4 人方案逐一审核（N×(N-1)=20 条并发）
   - 每人汇总收到的所有点评，自证/调整/反击
   - 收敛检查：≥3 个前区共识号 + 后区 ≥3 票 → 收敛 ✅
4. **未收敛兜底**（若 5 轮未收敛）— 加权投票排名 + 最终陈述
5. **首席裁定** — Opus 模型综合辩论记录 + 共识 + 权重 + 硬约束（连号/上期重叠 1-2），输出最终一注

---

## 原则

- 彩票为随机游戏，历史统计**不能**保证未来结果。输出必须声明：娱乐目的、概率本质、过往统计仅供参考。
- **只出一注**：不撒网、不分散火力，输出唯一最优单式。
- **时间戳规则（强制）**：`最后更新`、`预测生成时间` 使用北京时间 ISO-8601（`+08:00`）。

## 数据来源

`data/processed/dlt_draws.csv`（优先），否则回退 `data/raw/`。

## 硬约束（首席裁定必须遵守）

1. **连号**：前区 5 码至少包含一组连续号（如 14,15）
2. **上期重叠**：前区与上期重叠 **1 或 2 个**号
3. **历史去重**：不与历史任一期前区完全重合
4. **后区上限**：后区与上期重叠不超过 1 个

## 落盘约定

Workflow 完成后，结果由调用方（Agent）负责写入：

| 文件 | 内容 |
|------|------|
| `history/daletou_analysis.md` | 走势面板 + 结构快照 |
| `history/daletou_prediction.md` | 最终一注 + 选号逻辑 + 委员会辩论摘要 |

## 职责隔离

**仅大乐透**。其他彩种用各自独立 Skill。禁止数据采集、全流程编排。

- 不得输出多注方案（除非用户明确要求）
