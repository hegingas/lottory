# 彩票选号 · Dynamic Workflow

基于 Claude Code Workflow 的**大乐透、双色球、快乐八、排列5、七星彩**选号项目。每个彩种由多人委员会对抗验证 Workflow 驱动，独立提名 → 互审交锋 → 收敛裁定，输出一注推荐号码。

## 重要说明

彩票开奖具有随机性，仓库内任何统计、预测或组合方案**均不构成投资建议或中奖保证**，仅供学习与娱乐用途。

## 开奖模拟器

`scripts/simulate_lottery.py` — 每期机选 N 注 + 随机开奖，统计各奖级中奖情况并与理论概率对照（验证随机性与返奖率口径）：

```bash
python scripts/simulate_lottery.py                      # 全部彩种 × 100 万期 × 每期 5 注（约 1 分钟）
python scripts/simulate_lottery.py --type SSQ           # 只模拟双色球
python scripts/simulate_lottery.py --rounds 10000       # 改期数
python scripts/simulate_lottery.py --per-draw 10        # 每期机选 10 注
python scripts/simulate_lottery.py --seed 42 --show 3   # 固定种子 + 展示前 3 期开奖明细
python scripts/simulate_lottery.py --ssq-fuyun          # 双色球「特别规定」执行期（福运奖 3+0 生效，5 元）
python scripts/simulate_lottery.py --dlt-bigpool        # 大乐透奖池≥8 亿元档（固定奖升级 5000→6666 等）
python scripts/simulate_lottery.py --backend gpu        # 计算后端: auto/gpu/numpy/python(默认 auto 自动检测)
```

计算后端（100 万期 × 5 彩种全量耗时）：

| 后端 | 耗时 | 说明 |
|------|------|------|
| GPU（CuPy + RTX 5090） | ~1.2 秒 | 批量向量化 + one-hot 匹配,需 `pip install cupy-cuda12x[ctk]` |
| NumPy | ~13 秒 | 同为向量化,无需 GPU |
| 纯 Python | ~74 秒 | 逐期循环,零依赖兜底 |

每个命中条件独立成行输出注数（如双色球「四等奖 5+0」「四等奖 4+1」分开统计），并对照理论概率。规则口径为官方现行版本：双色球 2026 新规（福运奖：奖池≥15 亿启动、<3 亿停止，默认不执行）；大乐透 2026 新规（9 级合并为 7 级，奖池≥8 亿固定奖自动升级）；快乐八选十含「中 0 个回本 2 元」；七星彩为 2020-10 新版「前 6 位 + 后区 0-14」按位匹配。模拟结果仅用于概率验证，与真实开奖相互独立。

## 历史数据回测（GPU 向量化）

`scripts/backtest_all.py`（五彩种全量回测，深冻/热冷/结构分层验证）与 `scripts/backtest_funnel.py`（双色球漏斗方案对比）均支持 GPU 加速，全量回测约 1 秒完成：

```bash
python scripts/backtest_all.py              # 五彩种全量回测(auto: GPU→NumPy)
python scripts/backtest_all.py --backend gpu
python scripts/backtest_funnel.py           # 双色球 300 期漏斗回测
```

实现方式：全量历史一次性构造成计数矩阵，前缀累积一次性算出所有期的当前遗漏/历史最大遗漏/窗口频率（公共模块 `scripts/vec_utils.py`）。GPU 与 NumPy 后端输出逐字节一致。

回测方法论（v2，消除乐观偏差）：
- 数据三分离：训练 100 期 → 验证 100 期（只用于选参数）→ 测试集（只报告一次，不选参）
- 深冻误杀率 / 热冷区分度对照随机基线 + 正态近似显著性检验（z/p 值）
- 结构约束对照解析随机理论分布（连号/重号/奇偶/大小/和值）
- 快乐八随机基线按每期开出 20 个计算；funnel 方案 B 按 10 码候选池对比 10/33 基线

修正后结论：深冻在 SSQ/PL5/QXC 上显著低于随机（QXC 误杀率 12.4% vs 随机 28%，p≈1e-14），但排除量小不建议当主力；热/冷与统计打分与随机无显著差异；结构约束观测分布与随机理论吻合，仅形态合规参考。

## 全量技术指标回测（18 指标 × 5 彩种）

`scripts/backtest_indicators.py` — 15 期滚动窗口，号码级 12 指标（近15期频率/当前遗漏/遗漏比/历史最大遗漏/平均遗漏/上期重号/上期邻号/奇偶/大小/质合/012路/区间）+ 期级 6 指标（和值/跨度/奇偶形态/大小形态/连号/重号），全部分组对照随机基线 + z 检验，GPU 默认，~1 秒跑完。

结论（含数据质量发现）：
- 全部 ~200 个检验中，候选显著项经「未来泄漏修复 + 时间稳定性 + 号码频率均匀性」三重过滤后**无一存活**——所有技术指标无预测力，与独立随机理论一致
- **重大发现：大乐透早期开奖数据存在严重号码偏差**（前 1/3 期 29 号 +44.6%、33 号 +56.2%、16 号 −35.6%），后期回归正常；排列5 也有轻微不均匀（4 号 +5.2%）。该偏差曾让"历史最大遗漏/平均遗漏"指标出现 p<1e-7 的假信号，偏差回归后全部消失
- 双色球/快乐八/七星彩号码频率均匀性检验通过

数据交叉验证（2026-08-09，`scripts/verify_lottery_data.py` 可复跑）：
- 官方源全量核对：福彩 cwl.gov.cn API（SSQ/KL8）、体彩 sporttery.cn API（DLT gameNo=85 / PL5 gameNo=350133 / QXC gameNo=04），与本地 CSV 逐期逐字段对比，修复后 **SSQ 2048 期 / KL8 2031 期 / DLT 2907 期 / PL5 7685 期全部一致，0 不一致**
- 修复记录（manifest 已登记，修复前快照存 `data/raw/*_pre_official_fix_*.csv`）：KL8 279 期号码错误（2021~2025，每期差 1~4 个号，已抽查官方公告仲裁）；PL5 1 期（2019054）；QXC 3 期（2023142/2024102/2025100）；DLT 6 期（07034/07035/07043/07044/07052/07053，经 500.com + 当期新闻双重仲裁）
- 补全缺失：KL8 16 期（含 2020 上市首月）、SSQ/DLT 最新 2 期、PL5 最新 11 期
- 未补：七星彩 2020 前旧版 2498 期（7 位定位规则与现行 6+1 不同，本地按现行规则口径保留）
- **大乐透早期（2007~2011）29/33/35 号偏多、16 号偏少的偏差经双独立源 + 当期新闻确认是真实开奖特征（疑为早期开奖机/球组物理偏差），并非本地数据错误；数据修复后全部回测结论不变**

## Workflow 架构

```
Skill 触发
  └─→ Workflow 脚本
        ├─ Phase 1: 数据准备（读取 CSV，提取统计上下文）
        ├─ Phase 2: 并行独立提名（4-5 个 Agent 各自分析选号）
        ├─ Phase 3: 对抗验证循环（最多 5 轮，互审 → 自证 → 收敛检查）
        │    ├─ 收敛（≥3 共识）→ 进入裁定
        │    └─ 未收敛 → 加权投票 + 最终陈述 → 强制裁定
        └─ Phase 4: 首席裁定（Opus，综合辩论记录输出最终一注）
```
